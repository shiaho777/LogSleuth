**LogSleuth 0.4.0 — a scroll rail that shows the whole buffer, a search bar that reads like search, and a background watch that stops crash-looping your phone.**

`versionName` 0.4.0, `versionCode` 11.

Requires Android 8.0 (API 26)+.

This build is signed with the same key as 0.3.5, so it installs over 0.3.5 —
your settings, sessions and crash history stay where they are.

## Added

- **A rail down the right edge of the list.** It draws the whole buffer as a stack of coloured bands, one per slice, coloured by the worst level in that slice — so an error cluster shows up without scrolling or searching. Drag the thumb to jump, tap to jump there, and a pill shows `Line 1,234 of 20,000` while you do. (#124)
- **A search bar that reads like search.** The query, the hit counter, the clear button and the prev/next steppers now live in one filled pill, with the case toggle and close outside it. The Enter key jumps to the next hit. (#124)
- **Crash search navigates.** Previous and next, a hit counter, and the current match scrolls into view — the snippet first, then the saved surrounding logs. Back closes the search before it leaves the page. (#111)
- **Share a crash as plain text.** GitHub, Telegram and mail get `text/plain`; a very large stack goes out as a file instead of a truncated blob. Save offers a `.txt` next to the zip, and both include the surrounding logs that were saved with the crash. (#111)
- **Ignore or un-ignore a crashing app** from the crash screen itself, without hunting through the settings. (#111)
- **The filter editor can pick a package and a set of levels.** Creating a filter from a log line opens the editor prefilled — tag, pid, tid, uid, package, level and a truncated message — instead of silently saving a tag+pid rule you never asked for. Empty fields are ignored when matching. (#111)
- **Restore defaults** in Settings puts every preference back to its default, after a confirmation that says exactly what is kept. (#133)
- **The QQ group and the Bilibili space** are one tap away at the bottom of Settings, and both are in the README. (#129, #131)
- **Restart logging** in the overflow menu reconnects a stream that looks wedged, keeping the resume stamp so the ring buffer is not dumped again. (#111)
- **A documentation site**, in English and 简体中文: the guide, the developer reference and the release runbook. (#127)

## Improved

- **`logcat` reads the stock buffer set** — `main`, `system`, `crash` and `events`. `system_server` lives in the system buffer, so its lines finally show up. (#111)
- **The paused badge counts what you will actually see.** It used to count every line the engine delivered, while resuming promoted only the ones the filter admits — so the number it promised was never the number you got. It now follows the active filter and re-counts when the filter changes. (#124)
- **Opening search no longer leaves a blank band above the keyboard.** (#124)
- **The background crash watch runs as a `specialUse` service**, the type meant for long-lived work. It no longer runs into the six-hour-per-day cap that Android 15+ puts on `dataSync`, which is what turned the watcher into a crash loop. (#125)
- **The app targets Android 16 (API 36)**. (#120)
- **Release notes are written and reviewed like code.** They live in the repository next to the version they describe, in English and Chinese, and the release workflow refuses to publish without them. (#127)

## Fixed

- **The background crash watch could crash the app over and over** on Android 15 and later, and Samsung's battery watchdog noticed. The cause was a foreground-service type with a time limit the watcher could never stay under; a refused start now stops the service cleanly instead of taking the process down, and Settings says so when the system pauses the watch. (#125)

**LogSleuth 0.4.0 —— 右侧轨道把整个缓冲区摊开给你看，搜索栏终于像搜索，后台监看也不再把手机搞崩了。**

`versionName` 0.4.0，`versionCode` 11。

需要 Android 8.0（API 26）及以上。

这一版和 0.3.5 用的是同一把签名密钥，可以直接覆盖安装——设置、会话和崩溃记录都还在。

## 新增

- **日志列表右侧多了一条轨道。** 它把整个缓冲区画成一列彩色色带，每段取该段里最高的级别，错误聚集不用滚动也不必搜索就能看见。拖动滑块可以跳转，点一下就跳过去，拖动时气泡会显示「第 1,234 行 / 共 20,000 行」。(#124)
- **搜索栏终于像个搜索框。** 输入、命中计数、清除按钮和上/下一条都收进一颗实心胶囊，大小写开关和关闭放在外面。键盘回车键跳到下一条命中。(#124)
- **崩溃页的搜索可以前后跳转。** 有上一条/下一条、有命中计数，当前命中会自动滚到可见位置——先显示命中片段，再显示保存下来的上下文日志。返回键先关掉搜索，再离开页面。(#111)
- **崩溃可以按纯文本分享。** GitHub、Telegram 和邮箱拿到的都是 `text/plain`；特别大的栈会作为文件发出，而不是被截断的一团。保存时可以选 `.txt`，和 zip 一样都包含随崩溃保存的上下文日志。(#111)
- **崩溃页面里就能忽略或取消忽略**某个应用，不用再去设置里翻。(#111)
- **过滤器编辑器可以选应用和级别集合。** 从某一行日志创建过滤器时，会打开预填好的编辑器——tag、pid、tid、uid、应用、级别和截断后的消息——而不是偷偷塞一条你根本没要求的 tag+pid 规则。匹配时空字段会被忽略。(#111)
- **恢复默认设置**：设置里一个按钮把所有偏好恢复为默认值，确认框会写清楚哪些东西会被保留。(#133)
- **Q 群和哔哩哔哩**都在设置页底部，一键可达，README 里也都有。(#129, #131)
- **重新读取日志**在溢出菜单里，用来救回看起来卡住的流，并且保留续读位置，不会把环形缓冲再倒一遍。(#111)
- **文档站上线**，中英双语：使用指南、开发者文档和发版手册。(#127)

## 改进

- **`logcat` 现在读取默认的缓冲区组合**——`main`、`system`、`crash`、`events`。`system_server` 就住在 system 缓冲区里，它的日志终于能看到了。(#111)
- **暂停横幅的数字变成了你真正会看到的行数。** 以前它统计引擎收到的所有行，而恢复时只放行过滤器允许的那些，于是承诺的数字从来兑现不了。现在它跟着当前过滤器走，过滤器一变就重算。(#124)
- **打开搜索时，键盘上方不再留一条白色空白。** (#124)
- **后台崩溃监看改用 `specialUse` 类型**，这才是长期运行该用的类型。它不会再撞上 Android 15+ 给 `dataSync` 定的每天六小时上限——那个上限正是监看变成崩溃循环的原因。(#125)
- **应用现在以 Android 16（API 36）为目标。** (#120)
- **发行说明改成写下来、审过再发。** 它和版本说明一起躺在仓库里，中英双语，流水线没有它就直接拒绝发布。(#127)

## 修复

- **后台崩溃监看会在 Android 15 及以上反复把应用搞崩**，三星的耗电监控也盯上了这件事。根因是前台服务的类型带了一个监看永远满足不了的时间上限；现在启动被系统拒绝时，服务会干净地停下，而不是把整个进程带走，系统暂停监看时设置里也会如实说明。(#125)
