**LogSleuth 0.4.1 — a steadier stream and a safer update path: reconnect-safe logcat, verified resumable downloads, and fixes across recording, search, redaction and timestamps.**

`versionName` 0.4.1, `versionCode` 12.

Requires Android 8.0 (API 26)+.

This build is signed with the same key as 0.4.0, so it installs over 0.4.0 —
your settings, sessions and crash history stay where they are.

## Improved

- **Update downloads are verified and resumable.** The in-app updater checks the finished file against the release's advertised size, resumes from the bytes already on disk, throws away a stale partial file instead of appending to it, and says exactly why a transfer failed — HTTP status, incomplete file or stalled connection — in the app's language. (#159, closes #158; #177, closes #176)
- **The SDK reconnects without duplicating the log.** When the host app's `logcat` dies, the SDK resumes from the last delivered line instead of writing the whole buffered ring to disk a second time. (#139, closes #138)
- **Recording keeps the whole active filter.** pid, tid and uid — silently dropped when a recording started from the stream screen — now narrow the recording too, because the service receives the filter as one value instead of a hand-maintained set of extras. (#141, closes #140)
- **Search stays responsive on a busy stream.** Hit re-indexing runs at most once every 250 ms instead of up to 60 full scans a second, and the rail's severity fingerprint is computed on the composition thread so a buffer trim can no longer crash the screen. (#165, closes #164; #163, closes #162)
- **Pause, filters, search, recording and reconnects are serialized.** List state is read under the lock that owns it, superseded filter and search work is cancelled instead of landing late, recording start/stop and cap stops share one lifecycle lock, and the engine checks stream ownership under its own lock. (#143, closes #142; #145, closes #144; #147, closes #146; #149, closes #148)
- **Rotating the screen no longer re-runs the launch action.** A shared file is imported once, and notification deep links no longer stack the same screen again. (#161, closes #160)

## Fixed

- **Reconnects survive New Year and non-Gregorian locales.** The resume stamp now carries a full `yyyy-MM-dd` date built from a Gregorian calendar with US digits, so a stream that crosses midnight on 31 December resumes instead of asking for a date a year ahead; log timestamps no longer jump by 543 years on Buddhist-calendar devices. (#169, closes #168; #171, closes #170)
- **Saving or sharing a session reports failure instead of doing nothing.** Stream snapshots, range selections, exports and shares now show a message when they fail. (#151, closes #150; #157, closes #156)
- **Deleting a session no longer orphans its log file.** If the file cannot be removed, the session stays and a message explains why, so the delete can be retried from the list. (#173, closes #172)
- **Redaction masks the whole match** and also applies to crash reports before they are stored. (#155, closes #154)
- **Crash search matches the original text.** Searching a character whose lowercase form is longer (`İ`) no longer misplaces the highlight or crashes the screen. (#167, closes #166)
- **Live search hits follow their log line.** When the ring buffer evicts older rows, next/previous now jumps to the line that actually matched instead of a shifted position. (#179, closes #178)
- **Zip imports read the whole header**, so a shared bundle is no longer misclassified from a short first read. (#153, closes #152)
- **The README permission table matches the manifest**, including the restart-after-reboot permission and the `specialUse` foreground service. (#137, closes #136)

**LogSleuth 0.4.1 —— 更稳的日志流、更安全的更新：断线重连不再重复写日志，下载可校验可续传，录制、搜索、脱敏和时间戳一并修好。**

`versionName` 0.4.1，`versionCode` 12。

需要 Android 8.0（API 26）及以上。

这一版和 0.4.0 用的是同一把签名密钥，可以直接覆盖安装——设置、会话和崩溃记录都还在。

## 改进

- **更新下载会校验，也能续传。** 应用内更新器会核对完成文件与发行页公布的大小，从磁盘上已有的字节继续下载，丢弃过期的不完整文件而不是继续追加，并用应用当前语言说明失败原因——HTTP 状态码、文件不完整或连接停滞。(#159, closes #158; #177, closes #176)
- **SDK 重连不再重复写日志。** 宿主应用的 `logcat` 死掉后，SDK 从最后一条已交付的日志继续，而不是把整个缓冲区再写一遍到磁盘。(#139, closes #138)
- **录制会带上完整的当前过滤器。** 从日志流页面开始录制时，pid、tid 和 uid 以前会被悄悄丢掉；现在服务收到的是一整个过滤器值，而不是一份需要手工维护的 extra，录制范围会和屏幕上看到的一致。(#141, closes #140)
- **日志很多时搜索也不会把界面拖住。** 命中重建最多每 250 毫秒跑一次，而不是每秒最多 60 次全量扫描；右侧轨道的级别指纹改在组合线程计算，缓冲区淘汰旧行时不会再让页面崩溃。(#165, closes #164; #163, closes #162)
- **暂停、过滤、搜索、录制和重连都串行化了。** 列表状态在拥有它的锁内读取，过期的过滤和搜索任务会被取消而不是晚到覆盖，录制的开始、停止和容量上限停止共用一把生命周期锁，引擎也在自己的锁内检查日志流的归属。(#143, closes #142; #145, closes #144; #147, closes #146; #149, closes #148)
- **旋转屏幕不再重复执行启动动作。** 分享进来的文件只会导入一次，通知深链也不会把同一个页面重复压进返回栈。(#161, closes #160)

## 修复

- **跨年和非公历地区也能正常重连。** 续读时间戳现在带完整的 `yyyy-MM-dd` 日期，由公历和 US 数字生成，所以 12 月 31 日午夜断开的流会正常续读，而不是去请求一年后的日期；在佛历设备上，日志时间也不会再偏移 543 年。(#169, closes #168; #171, closes #170)
- **保存或分享会话失败时会提示，而不是毫无反应。** 日志流快照、范围选择、导出和分享失败时都会弹出提示。(#151, closes #150; #157, closes #156)
- **删除会话不会再留下孤儿日志文件。** 如果文件删不掉，会话会保留并说明原因，可以回到列表重试。(#173, closes #172)
- **脱敏会遮住整个命中片段**，并且在崩溃报告写入存储前也会执行。(#155, closes #154)
- **崩溃搜索按原始文本匹配。** 搜索小写形式更长的字符（如 `İ`）时，高亮不会错位，页面也不会崩溃。(#167, closes #166)
- **实时搜索命中跟着日志行走。** 环形缓冲淘汰旧行时，上一条/下一条会跳到真正命中的那一行，而不是错位后的位置。(#179, closes #178)
- **Zip 导入会读取完整文件头**，分享的压缩包不会再因为第一次读取太短而被误判。(#153, closes #152)
- **README 的权限表与清单文件一致**，补上了开机重启权限和 `specialUse` 前台服务。(#137, closes #136)
