# 录制与崩溃

有两个功能在后台运行：把流写成文件的录制会话，以及盯着「有东西挂了」的崩溃
监看。

## 录制一段会话

三种开始方式：

- 流界面顶栏的 **保存**，会询问保存当前看到的内容；
- 快捷设置里的 **录制磁贴**；
- 悬浮控件。

录制是一个前台服务，所以你用手机的时候它也在继续。它的通知显示行数，并提供
暂停、打书签和停止。书签会标记文件里的当前时刻，之后可以再找回来。

体积和时长上限在 **设置 → 录制** 里：最大体积（默认 64 MB）和最长时长
（0 表示不限）。碰到上限会话会自己停。

会话列在 **会话** 标签页。每个会话都可以逐行回放、搜索、导出成文本或 zip，
或者删除。

## 崩溃与 ANR 侦测

LogSleuth 盯三类故障：

| 类型 | 找什么 |
| --- | --- |
| Java 崩溃 | `AndroidRuntime` 标签里的 `FATAL EXCEPTION` |
| native 崩溃 | `Fatal signal` 以及 tombstone 的标记 |
| ANR | `ANR in <包名>` 与 `am_anr` 事件 |

侦测到之后，LogSleuth 会把事件连同它前后的日志一起存下来，所以拿到的是完整
的故事，而不只是一段栈。**设置 → 崩溃侦测** 里可以按类型开关，通知也可以按
应用或按崩溃类型分组。

**在崩溃里搜索。** 崩溃页的搜索覆盖堆栈和保存下来的附近日志，支持上一条/
下一条、有命中计数，当前命中会自动滚到可见位置——先显示命中片段，再显示它
周围的上下文。返回键先关掉搜索，再离开页面。

如果某个应用的崩溃只是噪音，可以在崩溃详情页忽略它所在的包；同一个页面也能
取消忽略。

**按纯文本分享。** GitHub、Telegram 和邮箱要的是 `text/plain`，所以分享动作
给的就是这个。堆栈特别大时会改成通过系统分享面板发送一个 `text/plain` 文件，
**保存**时则可以在 zip 之外选 `.txt`。两种方式都包含随崩溃保存的上下文日志。

## 后台崩溃监看

打开 **设置 → 后台监听崩溃** 之后，LogSleuth 会在你离开 App 后仍然保留一条
安静的前台服务，这样崩溃依然能被抓到，重启手机之后也照样有效。

有两个诚实的限制：

- Android 13 及以后，ADB 授权只在 LogSleuth 位于前台时有效，所以要在后台
  监看就得用 Shizuku 或 root。
- 如果系统拒绝让服务继续运行，开关会如实告诉你，而不是假装监看还在跑。重新
  打开一次应用，或者把开关关掉再打开，就可以恢复。

## 分享与导出

| 想分享什么 | 怎么做 |
| --- | --- |
| 一次崩溃 | 崩溃详情页以纯文本分享栈，或者导出带设备与应用信息的 zip |
| 一段会话 | 会话列表里导出文本或 zip |
| 你正在看的内容 | **上报** 标签页会引导你完成一次导出 |
| SDK 产出的文件 | SDK 把自己的日志打包成 zip，可以直接分享 |

纯文本分享会控制在系统 Intent 的大小限制内；特别大的栈会改成通过系统分享
面板发送一个 `text/plain` 文件。导出内容包含随崩溃保存的上下文日志。
