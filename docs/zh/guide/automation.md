# 自动化广播

LogSleuth 可以按你定义的规则监视实时日志流，把每一条匹配的日志行广播给
自动化应用——Tasker、MacroDroid，或任何能接收显式 Intent 的应用。这样
"当我的应用打出 X 日志时，执行 Y"就变成了一个自动化配置，不需要 ADB、
不需要 root，也不用轮询。

## 配置步骤

1. **设置 → 自动化 → 广播匹配的日志** 打开监视。运行时会有一条低优先级
   通知；离开应用后它继续工作，重启手机后也会自动恢复。
2. **管理自动化规则** 打开规则列表。每条规则包含：
   - **包含**——子串（或打开开关后用正则）匹配 tag 和消息。留空匹配所有行。
   - **Tag**——可选，对 tag 的子串约束。
   - **来源应用**——可选；只匹配该应用打出的行。
   - **目标应用**——必选。广播是*显式*的：只发给这个包，绝不发给其他应用。
   - **广播动作**——目标应用监听的 Intent 动作，默认
     `io.github.shiaho777.logsleuth.app.LOG_MATCH`。
   - **冷却时间**——同一规则两次广播的最小间隔秒数（0 表示不限制），
     防止高频日志行刷爆你的自动化应用。

## 在 Tasker 中接收

新建配置：**事件 → 收到 Intent**，动作填规则的动作名（默认如上）。
广播附带以下参数：

| 参数 | 含义 |
| --- | --- |
| `rule_name` | 命中的规则名 |
| `package` | 打出该行的应用包名（尽力解析） |
| `level` | `V`/`D`/`I`/`W`/`E`/`F` |
| `tag`、`message`、`raw` | 日志行内容（文本上限 8000 字符） |
| `pid`、`tid`、`uid` | 进程/线程/用户 id（`uid` 未知时为 -1） |
| `time` | 日志时间戳，毫秒 |

例子：一条包含 `FATAL EXCEPTION`、目标为 Tasker 的规则，配上 Tasker 里
"弹出提示并把 `%message` 存文件"的配置，就是一个覆盖整机所有应用的崩溃
警报。

## 隐私

广播是显式的，只发往你在每条规则里选定的应用。不做隐式广播，不出设备，
开关默认关闭，由你主动开启。
